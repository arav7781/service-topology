# `graph-model.json` schema

The structured source of truth. Layout, both renderers, the evidence report, and
the MCP server read this and nothing else. Generated by `build_graph_model.py` -
this file documents the contract, it is not a document you fill in.

---

## Top level

```json
{
  "schema": "topology-cartographer/graph-model",
  "schema_version": "1.0.0",
  "repo": "/absolute/path/to/the/analysed/repository",
  "scope": ["services/orders"],
  "stats": { "services": 3, "topics": 2, "edges": 10, "edges_code": 9 },
  "services": [],
  "topics": [],
  "external_systems": [],
  "edges": [],
  "warnings": [],
  "layout": {}
}
```

| Field | Meaning |
|---|---|
| `repo` | Where the scan ran. The only absolute path in the document. |
| `scope` | Subtrees the scan was restricted to; empty means the whole repository. |
| `stats` | Counts, including the `[CODE]`/`[INFERENCE]`/`[UNVERIFIED]` split. Derived - never hand-set. |
| `warnings` | Files that could not be read, extractors that failed. Omitted when empty. |
| `layout` | Added by `layout_graph.py`. Absent until then. |

No timestamp appears anywhere in this document, deliberately: a timestamp would
make every run differ from the last and destroy the determinism check.

## Nodes

Three buckets, one shape:

```json
{
  "id": "orders-svc",
  "kind": "service",
  "label": "orders-svc",
  "language": "go",
  "path": "services/orders",
  "source_evidence": ["services/orders/go.mod:1"],
  "attributes": { "files": "5", "openapi": "services/orders/api/openapi.yaml" }
}
```

| Field | Notes |
|---|---|
| `id` | Stable slug. The filename of a micro topology, and the key edges reference. Never renumbered between runs. |
| `kind` | `service` \| `topic` \| `datastore` \| `cache` \| `external_api` |
| `label` | What the box says. May contain `\n`; renderers convert it. |
| `language` | Detected from the manifest, or voted on by file extension. |
| `path` | Repository-relative service root. Empty for a node with no code here. |
| `source_evidence` | One or more `path:LINE`. Every node has at least one. |
| `attributes` | Free-form strings. Two are meaningful to renderers: `origin: referenced-only` on a service, `unresolved: true` on a topic. Both draw hollow. |

`services` holds `kind: service`, `topics` holds `kind: topic`, and
`external_systems` holds everything else.

## Edges

```json
{
  "from": "orders-svc",
  "to": "orders.created",
  "type": "produces",
  "protocol": "kafka",
  "method": "",
  "detail": "key=order_id",
  "evidence_tag": "CODE",
  "source": "services/orders/kafka/producer.go:20",
  "also_at": ["services/orders/kafka/producer.go:12"],
  "note": "",
  "extractor": "kafka-go"
}
```

| Field | Notes |
|---|---|
| `type` | `produces` (service -> topic), `consumes` (topic -> service), `calls` (service -> service or external API), `depends_on` (service -> datastore or cache) |
| `protocol` | `kafka` \| `http` \| `grpc` \| `sql` \| `redis` \| ... |
| `method` | `GET /orders/{id}`, `GetOrder`. The endpoint, when there is one. |
| `detail` | `key=order_id`, `group=billing`, `binding orderEvents-out-0`. |
| `evidence_tag` | `CODE` \| `INFERENCE` \| `UNVERIFIED`. Mandatory. |
| `source` | `path:LINE`. Mandatory. An edge without one is rejected by `validate_graph_model.py`. |
| `also_at` | Further sightings of the same binding. One arrow, several citations. |
| `note` | **Mandatory** when `evidence_tag` is not `CODE`: why it is not confirmed. |
| `extractor` | Which extractor produced it, for debugging a wrong edge. |

Empty optional fields are omitted from the JSON rather than written as `""`.

---

## What deduplication does

Two sightings of the same binding become one edge with two citations, not two
arrows. "The same binding" means matching `from`, `to`, `type`, `protocol`,
`method` and `detail` - except for `depends_on`, where `from`, `to` and `type`
are enough, because a service either uses a database or it does not.

A sighting with no label is folded into a labelled sighting of the same
relationship: a writer declared with a topic, and a send carrying a message key,
are one arrow labelled with the key, citing both lines.

## The `layout` block

Added by `layout_graph.py`; consumed by `render_drawio.py`.

```json
{
  "layout_version": "1.0.0",
  "diagrams": {
    "master": {
      "title": "Master topology",
      "focus": null,
      "width": 1376,
      "height": 442,
      "nodes": {
        "orders-svc": {"x": 40, "y": 40, "width": 160, "height": 50,
                       "layer": 0, "order": 0}
      },
      "edges": [{"index": 0, "from": "orders-svc", "to": "orders.created",
                 "waypoints": []}],
      "edge_count": 10
    },
    "micro/orders-svc": { "...": "focus is the service id" }
  }
}
```

`edges[].index` refers to the position in that diagram's own edge list. For a
micro diagram, that list is the deterministic subgraph for `focus`, so the
renderer recomputes it and the indices line up. `edge_count` exists so a
mismatch is caught rather than rendered as a wrong arrow.

## Invariants `validate_graph_model.py` enforces

- Every edge endpoint is a node declared in one of the three buckets.
- Every `source` matches `path/to/file:LINE`, and with `--repo`, the file exists
  and has at least that many lines.
- Every edge has a valid `evidence_tag`.
- Every non-`CODE` edge has a `note`.
- `produces` points at a topic; `consumes` starts at one.
- Every node has at least one `source_evidence` entry.
